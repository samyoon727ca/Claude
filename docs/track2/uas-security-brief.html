Track 1 · Spotlight

DrayTek Vigor300B — patch-diff to root RCE

  • Diffed the public 1.5.1.6 → 1.5.1.7 window → a silent hardening of mainfunction.cgi (unquoted → single-quoted args).
  • Ghidra decompile + ARM disasm: an incomplete-blocklist sanitizer — & and brace-expansion {cmd,arg} survive → OS command injection.
  • Runs as root (lighttpd drops no privilege); post-auth operator/admin.
  • Deduped to CVE-2024-45890 — the whole action= family is CVE'd (CVE-2024-45884…45893). No novel headroom on the 300B.
Point: This is the full reversing story in four beats — find the silent fix, decode the sanitizer from disassembly, establish impact (root) and auth, then dedup rigorously. The outcome being an n-day doesn't diminish the method; it demonstrates it.

Capstone · Result

Measured against ArduPilot SITL — the prediction held

Ran the MAVLink T&E harness against a stock software-in-the-loop autopilot: 4 of 5 SHALL requirements unmet — the missing-authentication cluster the model ranked at the top, plus cleartext telemetry.

  • signing — frames unsigned (T1/T5)
  • cmd_injection — unsigned command accepted (T1)
  • replay — replayed frame re-accepted (T5)
  • telemetry — mission data in cleartext (T4)

Same class as CVE-2026-1579 (PX4, signing off → unauthenticated SERIAL_CONTROL shell → RCE, CVSS 9.8, CISA ICSA-26-090-02) — cited & reproduced, not claimed novel. PX4 SITL re-run pending.

Point: The value isn't "SITL is insecure" — everyone knows that. It's that I predicted the failure from the threat model and then measured it against the exact SHALL requirements, reproducibly and benignly.
